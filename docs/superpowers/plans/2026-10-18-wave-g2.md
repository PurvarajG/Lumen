## G2.1 Frame timing set by the audience window (P0)

Files: `crates/lumen-media/src/player.rs`, `crates/lumen-media/tests/media.rs`, `crates/lumen-app/src/media.rs`, `crates/lumen-app/src/app.rs` (`Published`, the audience closure in `show_outputs`, `release_media_wait`), and `crates/lumen-app/src/transport.rs` only if `position_secs` changes.

Goal: each video frame stays on screen for a whole number of the **audience display's** refreshes, chosen the same way every time, with no 1/4-refresh splits.

1. **Stop deciding on the pacer thread.**
   - Keep the reader thread and the `sync_channel(READ_AHEAD)` of decoded frames.
   - Replace the pacer thread with a `FrameClock` behind `Arc<Mutex<…>>`. It holds `start: Option<Instant>`, `shown: u64` (frames shown), a lookahead `VecDeque<(u64, Vec<u8>)>` (at most 2) and the channel receiver.
   - Expose it as `MediaPlayer::frames(&self) -> FrameSource`, a cheap `Clone` handle that is `Send + Sync`.
2. Add `FrameSource::frame_at(&self, now: Instant, refresh: Duration) -> Option<Frame>`:
   - **First call:** anchor `start = now - refresh / 4`. Add a one-line comment saying why: the quarter-refresh offset keeps every frame's due time at least 1/4 refresh away from a vsync, so timing noise can't flip which refresh shows it.
   - **Every call:** top up the lookahead from the channel with `try_recv`. Frame `n` is due at `start + n / fps`. Return the newest frame whose due time ≤ `now` and drop older ones. Return `None` if that frame was already returned.
   - **Stall rule:** keep the G1.1 rule. If the oldest pending frame's due time + 250 ms < `now`, rebase `start` so that frame is due `now`, and keep the `shortcut:` comment.
   - **Paused:** return `None`. On the first call after resume, rebase as above.
   - `finished` becomes true only when the reader has ended **and** the lookahead and channel are empty. Keep every existing error, EOF and stop/reap behaviour, and the `stop()` joins.
   - `position_secs()` reads `shown / fps`, modulo the duration for looped clips, as in G1.7.
3. **Who calls it.**
   - When the audience window is open, its closure calls `frame_at(Instant::now(), refresh)`, where `refresh = ctx.input(|i| i.stable_dt)` clamped to 1/240–1/24 s. It uploads the frame into the shared video `TextureHandle` (`tex.set(…)` on the clone in `Published`), with `from_rgba_premultiplied` as now.
   - When the audience is closed, `MediaState::poll` in the root does the same with the root's `stable_dt`.
   - Add `video: Option<FrameSource>` to `Published`, plus a bool saying whether the audience drives playback, so only one of the two pulls frames.
4. **The first frame and the texture.** When a player loads, `MediaState` creates the `"lumen-video"` texture as a 2×2 black image, so the handle exists before any frame arrives. Add `FrameSource::has_frame()`, true once any frame has been returned. G1.3's media-wait release (`release_media_wait`) uses it instead of `image_texture.is_some()`, so the old picture is still held until a real frame arrives.
5. **Tests.** The selection runs on a pure function of times, so feed it simulated vsync times with ±1 ms noise:
   - 30 fps at 75 Hz: every frame is shown for exactly 2 or 3 refreshes; never 1 or 4.
   - 25 fps at 75 Hz: always 3.
   - 30 fps at 120 Hz: always 4.
   - 30 fps at 60 Hz: always 2.
   - A stall of 2 s, then normal: no burst, at most one frame per call.
   - Pause, then resume: none while paused, and no burst after.
   - Update the existing player tests to the new API.

**Acceptance**, with the release build and the test rig above:
- Create a 25 fps clip: `ffmpeg -f lavfi -i testsrc2=size=1920x1080:rate=25:duration=20 -pix_fmt yuv420p .local/qa/g1/motion25.mp4`. Point a copy of the show's cue 13 at it (`show-g2.lumen.json`).
- L27q audience, 30 fps clip: **at least 95% of frame times within 27 ± 3 or 40 ± 3 ms**, none at 13 or 53 ms. Mean 33 ± 2 ms.
- L27q audience, 25 fps clip: at least 95% within 40 ± 3 ms.
- Main window LIVE monitor at the same time: at least 28 fps for the 30 fps clip.
- Audience closed, laptop only: the main monitor shows the 30 fps clip at 33 ± 3 ms for at least 95% of frames.
- Record CPU with `top -l 2 -pid <pid> -stats cpu`.
- Put the before/after frame-time counts in the commit message.

## G2.3 Fit, Fill or Stretch for photos and videos (P1, user request)

The operator wants photos and videos that aren't 16:9 to fill the screen with no bars.

Files: `crates/lumen-core/src/model.rs`, `lumen-core` tests, `crates/lumen-app/src/render.rs`, `crates/lumen-app/src/inspector.rs`, `crates/lumen-app/src/panels.rs` (context menus), and `crates/lumen-app/src/add.rs`, `media.rs`, `app.rs` for constructor/pattern updates only.

1. **Model.**
   - Add `#[derive(Clone, Copy, Debug, Default, Serialize, Deserialize, PartialEq, Eq)] pub enum MediaFit { #[default] Fit, Fill, Stretch }`.
   - Add `#[serde(default)] fit: MediaFit` to `Background::Image` and `Background::Video`. Old files load as `Fit`, so there is no schema bump.
   - Export it from `lib.rs`.
   - Update every constructor and pattern. `grep -rn "Background::Image\|Background::Video" crates` lists `add.rs`, `app.rs`, `inspector.rs`, `media.rs`, `panels.rs`, `render.rs` and the core tests. Patterns that only need the path use `{ path, .. }`.
   - `MediaState::matches_background` compares the whole background. A fit-only change must **not** restart a playing video: compare with `fit` ignored when deciding to reload, and repaint with the new fit.
2. **Render.**
   - Add a pure `fn media_rect_uv(texture: Vec2, canvas: Rect, fit: MediaFit) -> (Rect, Rect)`:
     - Fit = `fitted(canvas, texture)` with full UV.
     - Fill = the full canvas with a centred UV crop to the canvas aspect.
     - Stretch = the full canvas with full UV.
   - Use it in `paint_scene` for image and video backgrounds (`painter.image(id, rect, uv, WHITE)`). PDF and deck pages stay Fit; say so in a comment. Everything that goes through `paint_scene` follows automatically: audience, live monitor, Preview, grid, running-order thumbnails and transitions.
   - Tests: a 4:3 texture on a 16:9 canvas for each mode, a 9:16 portrait for Fill, and the degenerate zero-size case.
3. **UI.**
   - Prepare inspector, background section: a `Scale` combo with "Fit (show bars)", "Fill screen (crop)" and "Stretch".
   - Present and Prepare: the right-click menu on a cue tile, and on a running-order row whose first slide is an image or video, gets a "Scale" sub-menu with the same three choices and a check on the current one. A row applies the choice to every image/video slide in that document. It marks the project dirty and makes one undo step.
   - Changing the live cue does not change the screen until it is sent again. That is the product rule: edits never change live output.
   - The menu says this in one small caption when the cue is live: "Applies the next time it goes live." The audience screen is never changed by an edit.
4. Do not add a show-wide default or an "Add files" option. Name that as skipped in STATUS.

**Acceptance.** Make a 4:3 photo (`ffmpeg -f lavfi -i testsrc2=size=1440x1080 -frames:v 1 .local/qa/g1/photo43.png`) and a portrait 9:16 clip. In the test show:
- Fit shows bars on the L27q audience.
- Set Fill through the context menu, send the cue: no bars.
- Stretch fills the screen, distorted.
- Capture the audience window for each.
- An old show file loads unchanged, and saving then loading round-trips `fit`.

## G2.4 Movable, dockable panels (P1, user request)

The operator sets up with a big running order and a small preview, and runs the programme with a big preview. They want to drag panels where they like, and each mode keeps its own arrangement.

Dependency: in `crates/lumen-app/Cargo.toml`, add `egui_dock = { version = "=0.18.0", features = ["serde"] }`. That is MIT, released 2025-10-31, and the release built for egui ^0.33; the workspace pins egui 0.33.3. Run `cargo tree -p lumen-app -i egui` to confirm there is only one egui version afterwards. If 0.18.0 does not build against egui 0.33.3, stop and record why; do not upgrade egui in this wave.

Files: `crates/lumen-app/Cargo.toml`, `src/app.rs` (layout in `update`, the toolbar button, state fields), `src/panels.rs` (splitting into panes), a new `src/dock.rs` (the TabViewer, default layouts, validation, persistence; keep it small), `src/settings.rs` (persisted layouts), `src/style.rs` (dock style from existing tokens), and `DESIGN.md`/`docs/UI.md`.

1. **Panes.** `enum Pane { RunningOrder, Macros, Preview, Cues, Live, Tools }`. Split the existing functions; don't rewrite them:
   - `panels::library`: RunningOrder (search, tabs, rows, Add files). Macros becomes its own pane using `macros_body`, which replaces the G1.5 collapsing header and `bottom_reserve`. Delete those and their test; the list simply fills its pane. "New document" stays Prepare-only.
   - `panels::slides`: Preview (heading, big preview, label, notes) and Cues (document heading and edit buttons, cue grid). The G1.4 "Up next" heading and the G1.6/G2.2 preview rules move with Preview.
   - `panels::inspector`: Live (LIVE monitor, transport, Transition picker, now-playing strip) and Tools (Present: tool tabs; Prepare: the slide inspector and Overlays). Settings, when open, show inside the Tools pane, as they do in the right column today.
   - The G1.4 `scroll_to_armed` behaviour keeps working in RunningOrder and Cues.
2. **TabViewer** (`dock.rs`):
   - `title`: "Running order", "Macros", "Preview", "Cues", "Live", and "Tools" or "Inspector" in Prepare.
   - `ui` calls the pane function.
   - `closeable` is false for every pane, so a panel can never be lost.
   - Floating windows are off (`DockArea::show_window_close_buttons(false)`, and no window surfaces: `allowed_in_windows` false).
   - Tabs can be dragged to any edge to split, or onto a tab bar to stack. The separators can be resized.
3. **Default layouts:**
   - **Present** (today's arrangement): RunningOrder on the left (about 22%), with Macros stacked as a second tab in the same node. In the centre, Preview (about 58% of the height) above Cues. On the right (about 28%), Live above Tools.
   - **Prepare**: RunningOrder on the left (about 34%) above Macros (about 25% of its height). In the centre, Cues (large) below a small Preview (about 30% of the height). On the right (about 32%), Tools (Inspector), with Live stacked as a second tab.
4. **Persist each mode.**
   - Add `#[serde(default)] layouts: Layouts { present: Option<DockState<Pane>>, prepare: Option<DockState<Pane>> }` to `Settings`.
   - Treat it as untrusted input: on load, check that each mode's state contains every `Pane` exactly once. Otherwise use the default and set the existing settings notice ("Panel layout was reset").
   - Save through the existing `persist_settings` path: when switching modes, on exit, and at most every 5 s while the serialized layout differs from the last saved one (compare `serde_json` strings; no change events needed).
   - Never panic on a bad layout.
5. **Toolbar.** Add a "Reset layout" button after Shortcuts. It resets only the current mode's layout to the default.
6. **Shell.** The toolbar (`TopBottomPanel::top`) and status bar stay fixed. Remove the left and right `SidePanel`s; `DockArea` fills the `CentralPanel`.
   - Borrowing: `let mut dock = self.dock_for_mode.take()`, show it with a TabViewer holding `&mut self`, then put it back.
   - Keyboard shortcuts, the drop overlay, the modals and the outputs must keep working: they run outside the dock.
7. **Style.** Map `egui_dock::Style` from `style.rs` tokens only:
   - Tab bar `PANEL`, active tab `TEXT` on `RAISED` with a 2 pt `SAFFRON` underline, inactive `TEXT_DIM`.
   - Separators `LINE`, 4 pt wide hit area, drop preview `SAFFRON` at low alpha.
   - Corner radius 3.
   - No new colours.
8. **Tests:** layout validation (complete / missing pane / duplicate pane / unparsable JSON → default), that both default layouts contain every pane exactly once, and a settings round trip with layouts.

**Acceptance**, native, with window captures to `.local/qa/g1/shots/g24-*.png`:

- Drag the Preview tab onto the right edge of the Cues node with a CGEvent drag. Write `drag.swift x0 y0 x1 y1`: mouse down, about 10 moves over 300 ms, mouse up. The panel moves.
- Resize a separator.
- Switch modes and back: each mode keeps its own layout.
